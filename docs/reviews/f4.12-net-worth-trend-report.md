## What changed

- **New pure logic** `flutter/lib/money/net_worth_history.dart`: `netWorthHistoryOf`,
  `upsertNetWorthSnapshot` (replace-or-append, sorted, capped at
  `maxNetWorthMonths` = 24), `priorNetWorthValue` (most recent month strictly
  before the current one), `netWorthTrend` (peso delta always; percent only off a
  positive base and within a 10x sane bound), and `recordNetWorthSnapshot`
  (returns the same map instance when nothing changed).
- **Persistence** `flutter/lib/data/backup.dart`: `sanitizeData` now emits a
  CONDITIONAL `settings.netWorthHistory` key via `_netWorthHistoryClean` (drops
  malformed rows, de-duplicates months last-wins, sorts, caps at
  `maxNetWorthMonths`). Absent when empty, so RN-shaped fixtures never gain the
  key and the golden key-set contract holds. Stored under `settings` next to the
  other Flutter-era collections (treats, paluwagans, steadyPay,
  expansionProgress), which is the established conditional-key precedent.
- **Recording** `flutter/lib/data/store.dart`: `recordNetWorthSnapshot` mirrors
  `postDueRecurring` (canWrite guard, identity no-op probe, folded through
  `_mutate`). Uses `netWorthParts(data, fx: fxTable)`, the same figure the hero
  shows.
- **Trigger** `flutter/lib/main.dart`: called from the UI layer on startup (after
  `load()` completes) and on resume, deliberately NOT inside `store.load()`.
- **Render** `flutter/lib/screens/overview.dart`: `_netWorthHero` shows
  `_netWorthTrendLine` only when a prior month exists; otherwise the honest
  position-only card is unchanged.
- **Fixture** `flutter/test/screens_shot.dart`: the lived-in fixture gains two
  prior months so the hero trend renders in every future Home shot.
- **Tests**: `flutter/test/net_worth_history_test.dart` and
  `flutter/test/net_worth_history_sanitize_test.dart`.

## What did NOT change

No money math, signs, currency, precision, rounding, account relationships,
transaction classification, or reconciliation. Every snapshot is
`netWorthParts` verbatim. No schema version bump. No destructive migration and
no persisted-data transform of existing fields: the change is purely ADDITIVE
(a new conditional settings key). Existing users start with an empty trail and
the trend appears once a second month is recorded. No security, privacy, auth,
permission, or telemetry change. Presentation adds one line to one card.

## Key design decision: recording lives in the UI layer, not load()

`recordNetWorthSnapshot` writes a figure keyed on `DateTime.now()`. Putting it in
`store.load()` made the stored blob time-dependent and broke the deterministic
backup round-trip tests (caught during development: `backup_export_golden_test`
"importing over existing data keeps the outgoing blob under the side key"). It is
therefore triggered from `main.dart`'s startup and resume paths, which headless
data tests never exercise, keeping the pure data path deterministic.

## Independent QA (qa-tester)

One must-fix and three smaller findings, all fixed and re-verified:

1. (MUST) `_netWorthHistoryClean` coerced a non-numeric/missing `value` to PHP 0
   and KEPT the row, diverging from the runtime reader which drops it. A
   malformed backup row would have produced a fabricated "Up <entire net worth>"
   trend. Fixed to require a finite `num` before keeping, matching
   `netWorthHistoryOf`; guarded by an updated sanitize test.
2. Cap hardcoded `24` instead of `maxNetWorthMonths` (latent drift if the
   constant is ever raised, since `_save` does not re-sanitize). Fixed to use the
   shared constant.
3. Percent off a rounding-level positive base exploded (e.g. "9,999,900%").
   Fixed: percent suppressed beyond a 10x change; guarded by a new pure test.
4. A sub-centavo dip rendered "Down PHP 0". Fixed: treated as flat below half a
   centavo.

## Independent journey test (journey-tester)

Added one journey to `flutter/test/journeys_test.dart`: "the net worth trail
records exactly what was spent, and survives a backup". It records last month's
snapshot, logs a PHP 250.75 expense from Cash through the real Log sheet, records
this month's snapshot, then asserts:
- a DIRECTIONAL money invariant: net worth fell by exactly 250.75 and Cash fell
  by exactly 250.75 (inaction cannot satisfy it);
- each stored value equals `netWorthParts` at the moment it was taken (never a
  literal), the trail is two months in order, and the month-to-month step equals
  the money that moved;
- the data-safety heart: `exportBackupText` -> wipe device -> fresh store loads
  empty -> `importBackupText` -> `netWorthHistoryOf` equals the pre-export
  history, to the centavo.

Proved-it-fails: breaking the restore leg (`value + 1` in `_netWorthHistoryClean`)
turned the round-trip assertion red (`at location [0]['value'] is <15001.0>
instead of <15000.0> ... a restore onto a new phone loses the from-last-month
history`), then restored. Full `journeys_test.dart` green (18/18).

Named seams the journey deliberately did not cover (for a future pass): the
rendered hero string (a formatter concern, kept out of a money journey by the
file's rules), a multi-currency snapshot surviving a base-currency change across
a restore, and the 24-month cap driven through a real restore (all covered in
the unit and sanitize tests).
