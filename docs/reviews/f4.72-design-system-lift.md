# f4.72 Design-system lift

Phase: the first design phase of the founder-approved "Design and UX overhaul,
keep the brain", after Phase 0 (multi-currency bugs, f4.69 and f4.70) and the
f4.71 category-at-log-time write path. Presentation only.

## Scope

Three small primitives that raise the perceived quality of the dashboard
without touching a single computed number.

1. **`SalapifyCard`** (new, `lib/widgets/salapify_card.dart`). The ordinary
   boxed card, once: `Barako.card` fill, `Radii.card` border, one interior
   padding (`Insets.card`), an optional inside-a-card `kicker` with exactly one
   `Gap.sm` gap to the body, and an optional whole-card `onTap` whose ripple
   clips to the card radius. It replaces the hand-rolled
   `Container(decoration: BoxDecoration(...), padding: Insets.card)` pattern
   that had drifted across screens.

2. **`AppText.sectionTitle` + `SectionTitle`** (new tier in
   `lib/typography.dart`, widget in `lib/widgets/section.dart`). A page-level
   section band heading, one clear tier above the muted 12/w600 card kicker:
   13/w800 heavy, full ink, tighter tracking. Applied to the four Insights
   page bands (DO NEXT, THIS MONTH, THE BIGGER PICTURE, TOOLS) so the page
   reads as sections rather than a flat stack of equal labels.

3. **Hero number roll-ups**. The existing `CountUpText` widget, wired onto the
   Accounts net-worth hero and both faces of the safe-to-spend card. The
   figure rolls up when it is visible and stays a plain figure when it is
   masked by the privacy eye (dots cannot roll).

## What did NOT change

No money value, sign, currency, precision, rounding, account relationship,
transaction classification, calculation, reconciliation, schema, migration, or
stored data. `CountUpText` animates the DISPLAY of a value computed upstream and
never alters it. `SalapifyCard` reproduces the exact prior decoration and
padding. No new bundled asset: ships over the air.

## Adoption scope, deliberately bounded

`SalapifyCard` is adopted on two surfaces (the safe-to-spend card and the three
bills-and-spending cards), not swept across every screen. Because the primitive
renders pixel-identically to the still-hand-rolled cards, an adopted card and a
not-yet-adopted card are visually indistinguishable, so there is no jarring
inconsistency for a user and a full sweep would be diff for zero visual payoff.
Incremental adoption is the smallest correct change. `SectionTitle` is applied
to the Insights bands only this phase.

## Independent review (flutter-ux-craftsman, full diff)

Verdict: clean, faithful, correctly-scoped, NO must-fix. Const discipline
correct everywhere; stamp bumped and within the cap.

Two should-fix applied, both about honesty over flourish:

- **Reduce-motion.** `CountUpText` now reads `MediaQuery.disableAnimations` and
  falls back to a plain figure when the OS "reduce motion" setting is on, so a
  vestibular-sensitive user does not see the two biggest hero numbers roll.
- **Negative figures.** A negative value (a negative safe-to-spend buffer, an
  underwater net worth) no longer rolls up from zero, which would briefly read
  rosier than the truth on the one figure the card exists to be honest about;
  it renders at its true value at once.

Nits applied: a lone non-const `SizedBox` in an Insights band; the roll-up test
strengthened to prove the number actually MOVES (destination figure absent at
frame zero, present after settle), not merely that `CountUpText` exists.

Accessibility of the roll confirmed correct: the outer `Semantics(label:)`
speaks the final value once and the `ExcludeSemantics` swallows `CountUpText`'s
own announcement, so there is no double announcement and no digits-rolling-by
chatter.

## Validation

- `flutter analyze`: 0 issues on the whole tree (run after adding the test).
- New `test/design_system_test.dart`: SectionTitle is a distinct heavier tier
  than the card kicker; SalapifyCard applies the card decoration and one kicker
  gap and is tappable; the safe-to-spend figure rolls when visible and does not
  when masked; CountUpText honors reduce-motion and does not roll a negative up
  from zero.
- Break-then-prove on the two load-bearing guards: SectionTitle weight to medium
  reddened the tier test (Expected w800 Actual w600); forcing the buffer figure
  to a plain Text reddened the rolls-up test (Found 0 CountUpText). Both
  restored after the run reported.
- Three existing `safe_to_spend_card_test` cases went red because the roll
  starts at zero and they read the figure after one frame; fixed by settling
  the roll in the test helper (`pumpAndSettle`). Assertions unchanged; no
  product behaviour changed.
- Rendered dark and looked at, and sent to the founder: safe-to-spend,
  bills-and-spending, the Accounts net-worth hero, and Insights.

## Deferred

- A guard that new cards must use `SalapifyCard`, so the drift cannot regrow.
- `SectionTitle` on other screens with page bands (e.g. bills-and-spending's
  own THIS MONTH / YOUR RECURRING BILLS / COMING UP).
- A committed pixel baseline for these screens stays out, per the standing
  anti-flake rule (deterministic layout-metric tests remain the gate).
