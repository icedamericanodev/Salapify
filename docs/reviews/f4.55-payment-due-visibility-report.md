# f4.55 Payment due dates: surfacing the holiday-aware engine

Scope: Phase 2 of the founder's payment-reminder request. Investigation found
that a holiday-aware next-due-date engine and a bank-adjusted payment reminder
already exist in Salapify, built and golden-tested against the real RN app
(`money/phcalendar.dart`, `money/commitments.dart`'s `bankDueDate`, and the
`bills` toggle in `money/reminders.dart`) but were never SURFACED anywhere the
founder or a user would actually see them: no due-date preview in the add-debt
flow, no due-date line in Accounts, and the reminder itself is off by default
with no discoverable prompt to turn it on. Phase 2 is therefore presentation
plus one small, explicit opt-in permission flow, not a new calendar or
scheduler.

The founder chose, when asked: offer the reminder opt-in right inside the
wizard, at the moment it is useful, rather than leaving it buried in Settings.

## What changed

- **Two shared display helpers** in `money/commitments.dart`: `shortDueDate`
  ("Jun 15") and `daysUntilWords` ("in 3 days" / "today" / "tomorrow" /
  "yesterday" / "N days ago"), so the wizard, the Accounts row, and any future
  screen speak one date vocabulary. Pure functions, unit tested, proven by
  break-then-prove.
- **A live "Next payment" preview** in the debt wizard's Payment Schedule step:
  as a due day (or, for a card, a statement day plus grace days) is typed, the
  SAME golden-locked `bankDueDate` the `bills` reminder itself reads resolves a
  real bank-adjusted date, shown with the reason when weekends or a Philippine
  holiday moved it. Nothing new is computed; this only displays what the
  engine already knows.
- **A one-time reminder opt-in**, offered right after a successful save, ONLY
  when: the device can show notifications (`Reminders.supported`, the exact
  gate onboarding's own nudge step already uses), the saved debt has a
  resolvable schedule, the `bills` reminder is not already on, and it has
  never been offered before (a new `settings.billReminderOffered` flag,
  written the moment the sheet opens regardless of the answer, so a person
  editing the same card repeatedly is asked once, not on every save). Enabling
  routes through the exact same two calls the Notifications and security
  screen's toggle uses (`store.setNotifPref('bills', true)` then
  `Reminders.reschedule`), and a refusal shows the identical guidance sentence
  that screen already shows. One permission story across the app, not two.
- **A "Due Jun 15 · in 3 days" line** on debt rows in the Accounts category
  groups (plain rows and the rich credit-card tile), gated identically to the
  `bills` reminder (`remaining > 0`, a resolvable schedule) so the promise on
  screen and the reminder that actually fires can never disagree.

## What was found and fixed before shipping

Found while rendering, reviewing, and through an independent qa-tester pass
that specifically hunted for the one thing that mattered most: can the UI
ever promise a reminder the engine would not actually send.

- **A truncation bug (found rendering).** The first render showed the Loans
  row cutting off mid-word: `Due Sep 7 · in 18 days (adjusted for a S...`. A
  Philippine holiday name (for example "Feast of the Immaculate Conception of
  Mary") can run far longer than "a Saturday," and this compact row is one
  line. Fixed by dropping the specific reason from the Accounts row (it now
  says "(adjusted)"); the full explanation still has room in the wizard's
  roomier preview callout, which wraps rather than truncates.
- **A nag risk (found in self-review).** The opt-in's only original gate was
  "the bills reminder is not already on," so editing the SAME card a second
  time, for any reason, would ask again, and a third time would ask a third
  time. Fixed with a `settings.billReminderOffered` flag, written the moment
  the sheet opens whatever the person answers, so the ask happens once per
  install, not once per save.
- **A reminder/engine mismatch (SHOULD-FIX, found by the qa-tester pass, then
  fixed).** `_previewDue`, the wizard's live preview and the exact gate the
  opt-in itself checks, did not require `remaining > 0`, unlike the Accounts
  row's `_dueMeta` and the `bills` reminder's own gate in `reminders.dart`. A
  debt saved with a due day but a zero balance (a real, explicitly supported
  state, "0 if none") would show "Next payment: ..." and could trigger the
  reminder opt-in for a debt the reminder engine would never actually
  schedule. Fixed: `_previewDue` now requires `remaining > 0`, the same rule
  everywhere else already follows. Locked by a new test, proven by
  break-then-prove.
- **A misleading-error risk (MINOR, fixed).** The reminder opt-in was awaited
  inside the SAME try/catch that reports a save failure, so an exception in
  the optional post-save UI (unlikely, since `Reminders`' own calls already
  swallow their exceptions) could have mislabelled a successful save as
  "Nothing was changed." Fixed with its own try/catch around just the opt-in
  call.
- **A clarity gap (MINOR, fixed).** The wizard shows a due day field for every
  debt type and the statement-day-plus-grace-days fields for a card, with no
  explanation that an explicit due day always wins when both are filled in
  (pre-existing engine behavior, newly visible now that a preview shows it).
  Fixed: the due day field's helper text says so for cards.
- **Accepted, no code change.** A brief window between persisting the `bills`
  toggle and the OS scheduling call completing, if the widget is disposed
  mid-await; self-heals on the next app resume (main.dart already reschedules
  on every resume). Matches an existing accepted pattern elsewhere in the
  reminder system.

The qa-tester pass also confirmed, by direct inspection, that the Accounts
row's gating, the overflow handling on both surfaces, the privacy behavior (no
peso figure ever appears in a due-date line), and the invalid-input handling
(a junk `dueDay`, a debt with no schedule) were all already correct.

## What did NOT change

`money/phcalendar.dart`, `money/commitments.dart`'s `bankDueDate` and
`_rawDueCandidates`, and `money/reminders.dart`'s `bills` block are untouched.
No new holiday data, no new reminder lead time, no new toggle granularity. The
Chinese New Year table's 2026-2028 window and the absence of movable Islamic
holidays (Eid'l Fitr, Eid'l Adha, proclaimed too late to bake in) are pre-
existing, deliberate, fail-safe limits of the underlying engine (an unlisted
date is simply not adjusted, never adjusted wrongly) and are unchanged by this
phase. No schema change: `dueDay`, `statementDay`, `graceDays`, `remaining` all
already existed. The reminder opt-in never auto-enables anything in the
background; it only appears after an explicit save, and only the person's own
tap on "Enable" turns the toggle on.

## Validation

- `flutter analyze`: 0 issues on the pinned 3.44.6.
- Full suite green: 3006 pass.
- New tests: `commitments_display_test.dart` (pure-function unit tests for the
  two display helpers, proven by break-then-prove), a wizard existence test
  proving the preview appears once a due day is entered and is absent before,
  a wizard test proving a zero-balance debt gets no preview even with a due
  day set (the QA-caught fix above, proven by break-then-prove), and an
  Accounts test proving the "Due" line appears for an owed debt with a
  schedule and is absent for a paid-off one.
- `debts_screen_test.dart`'s `pumpAndSettle` timeout on the coupled save flow,
  caused by `Reminders.supported == false` correctly suppressing the opt-in in
  the test environment, was traced and confirmed rather than worked around.
- Rendered the wizard's schedule step and the Accounts credit-card and loan
  rows dark, looked, caught and fixed the truncation defect above, re-rendered,
  and sent the founder the PNGs.

## Deferred / known limitations

- The specific holiday/weekend reason is shown only in the wizard's roomier
  preview, not on the compact Accounts row (the truncation fix above).
- No richer due-date detail (a due-date breakdown, statement cut date) was
  added to the account/card detail screen; the Debts screen's own forecast
  display already covers that and was left untouched.

## Delivery

Dart only; no new asset, no new dependency, no native change. Ships over the
air. Stamp f4.55. Nothing merged or released by this report.
