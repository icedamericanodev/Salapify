# f4.41 Money Mindset Impact card fixes

Stamp: f4.41
Branch: claude/mindset-impact-fixes
Type: presentation only, ships over the air (Shorebird patch)

## Scope

The founder asked to review the recent Impact-step work (f4.37 to f4.39), fix any
issues, and approve unless something major turned up. An independent qa-tester pass
returned five real findings, all presentation, none money-math, none major. All five
are fixed here.

## Findings fixed

1. Delay-chip overflow. The goal delay chip was a bare, non-flexible child with an
   unbounded Text, so a long delay ("about 120 months later") could RenderFlex-
   overflow at 320dp / large text. Now wrapped in Flexible + scale-down FittedBox,
   and _statusPill's text is capped to one line with ellipsis.
2. Over-alarm on tiny emergency buys. Because the goal pace is ceil-rounded to the
   whole peso, the delay chip fires for near-any amount, so "significant" (which
   drove the strong-red chip and the "Careful" lead) was effectively always true,
   even for a PHP100 buy the same card called "a small slice". "Significant" is now
   judged by SIZE only (pct >= 25); a small buy stays quiet, the strong-red is
   reserved for a real bite, and the honest delay chip still shows in the standard
   warning tone.
3. "More than" contradiction. "more than the PHPX you still need" could show when
   the buy was actually slightly less, because it triggered on the rounded percent
   (99.75% rounds to 100%). The branch now compares pesos directly (amt > remaining).
4. Buffer status vs runway row mismatch. The buffer pill thresholded on the raw
   runway while the detail row displayed a one-decimal value, so 0.96 showed
   "1.0 months left" beside a "Thin" pill. The pill now thresholds on the same
   one-decimal value the row displays.
5. Blank goal name. A whitespace-only goal name left a gap ("put toward  instead").
   It now falls back to "this goal", matching goalTradeoff.

## What did NOT change

- No money value, sign, currency, precision, rounding of a stored figure, account
  relationship, transaction classification, calculation, reconciliation, schema, or
  stored data. Finding 3's fix changed a display branch condition, not a money value.
  Every figure is still an existing tested engine output.
- Read-only money; no write path touched.
