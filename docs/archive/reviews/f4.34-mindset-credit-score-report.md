# f4.34 Credit Decision-Score reconciliation, report

Founder-approved fix of the f4.21 deferred item, verified by a PH bank officer
before building.

## The bug

For the Credit/BNPL path the flow's _decision passed the FULL price as both
cashNow (immediate cash out) and monthlyLoad (ongoing monthly bite), and no
credit markup. So a 20,000 buy over 6 months was scored as if 20,000 left today
AND 20,000 left every month, which tanked every credit score. The engine's own
docstring already specified the correct inputs (first installment, ongoing
installment, markup = extra/price); only the flow's call site was wrong. The old,
now-deleted mindset.dart screen already did it correctly.

## The fix (bank-officer verified: "correct, ship it")

- New creditScoreInputs(plan) helper in mindset_credit.dart, so the wiring is
  pinned and testable: cashNow = plan.monthly (first installment), monthlyLoad =
  plan.monthly (ongoing installment), creditMarkup = extraCost / price (a true 0%
  plan yields 0, so the engine's markup penalty is skipped).
- lib/screens/mindset_flow.dart _decision uses it for MindsetMode.credit;
  one-time and subscription are untouched.
- The goal card weighs a credit buy against the TOTAL repaid (price + fee), not
  the sticker price (bank-officer note), since that is what truly competes with
  the goal.

The bank officer confirmed this is not double-counting (the installment answers
"can your cashflow carry it", the markup answers "are you overpaying"), that a
spread plan legitimately easing immediate cash is honest, and that the lock-in
message is carried by the card's total-paid and real-cost-per-year figures
(shown since f4.21). Optional polish was flagged and deferred (a lock-in-term
nudge; prompting to log a proceeded plan so stacking is seen next time).

## Money and data

Money-methodology change to the credit score only. One-time and subscription
scoring are unchanged. The what-if spectrum is one-time-only, so it is
unaffected. No storage, no schema.

## Validation

- flutter analyze: 0 issues. Full suite green.
- New unit vectors (mindset_credit_test): creditScoreInputs returns
  installment / installment / markup; a 0% plan has no markup.
- New widget test (mindset_flow_test): a ~3,433 installment against 32,000 income
  is NOT scored "Big impact", which the old full-price bug would have produced.

## Deferred

The bank officer's optional polish (lock-in-term nudge; log-the-plan prompt); a
broader sleeker pass.

## Risks

Low to moderate: it changes the credit score, but the model was bank-officer
verified, matches the engine's documented contract and the old screen's proven
behavior, is pinned by vectors, and touches only the credit path. Ships over the
air.
